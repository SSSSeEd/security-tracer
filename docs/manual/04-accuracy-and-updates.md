# 04 正確性(ハルシネーション対策)と情報更新

このアプリの存在理由は「正しい知識を、新しい情報に更新し続けながら学ぶ」こと。LLM が書く以上、**仕組みで誤りを止める**設計になっている。別テーマでも最優先で踏襲する。

## 1. 書いてよいことの条件
1. 公的機関・標準化団体・公式ドキュメントなど**一次情報で確認できること**だけ書く。確認できないことは書かない。「よくある助言」でも一次情報が無ければ書かない(例: 構成プロファイルの具体的な用途は書かず、レッスンのラボ説明に留めた)。
2. 確認の方法: 一次情報のページを WebFetch 等で**実際に開いて**読む。検索結果の要約や記憶で書かない。本文が取得できなかった(PDFが途中で切れる、条文が取れない等)なら**保留**にして ROADMAP に「確認できてから」と残す(実例: e-Govの刑法条文、IPA解説書PDF、いずれも保留中)。
3. 数値の目安・モデルは「単純化した例」「説明用の仮の値」「例示」と本文に明記。
4. 例の会社名・ドメイン・電話番号・IPは**架空**(example ドメイン、文書用IP帯 192.0.2.0/24 等)。実在の組織・個人を例に出さない。攻撃者メールにも `example.invalid` を使った。
5. 実際の攻撃や悪用に使える手順・コードにしない。ラボは架空データのみで実通信・実行をしない。仕組みと検知・防御を見せる。
6. 法令・制度は「法的助言ではない」と明記し、確認できなかった条番号や罰則は `unconfirmed:true` で「要確認」と画面に出す。

## 2. 機械的な強制 `node tools/check.js`(依存なし、node のみ。**コミット前に必ず OK を確認**)
検査している内容(実装済み):
- index.html の script 一覧と `js/widgets/*.js` の食い違い、存在しないファイル。
- sw.js のキャッシュ一覧に全 script と vendor の `.js/.wasm` があるか。
- ウィジェットの group が `ST.LAB_GROUPS` にあるか、ラボに name/desc/order(数値)があるか。
- レッスン: 参照ウィジェット・用語・出典が登録済みか、**出典 `src` が1つ以上**、`practice` の登録、`requires` が配列で、存在するid、自己参照なし、**循環なし**。
- 用語: lab/sim の登録、**src 1つ以上**、本文中 `[[…]]` のリンク先存在。レッスン本文・シナリオ・ニュースの用語参照も同様。
- クイズ: `term` と `exp` が必須、term 登録済み。
- 出典: org/label がある、url が `https://` で始まる、**確認日が YYYY-MM-DD**。
- 参考表示: どこからも引用されていない出典(整理の目安)。
- **公開リポジトリのスキャン**: 全テキストファイルのメールアドレス・電話番号・秘密鍵・トークンの形(`scan-ok` マーカーで除外)。
別テーマでも tools/check.js をほぼそのまま持っていき、データ名(ST.COURSES など)が同じなら変更不要。テーマ固有の検査(注意枠など)は足す。

`tools/test.js` は `node:test` による core.js の単体テスト(19件)。ブラウザ用の core.js をダミーの window で読み込む方式。復習スケジュールなど純粋関数のロジックを足したら、テストを足す。

## 3. 画面に出す仕組み(読む人に誤りを疑わせる)
- ホームに注意書き: 解説は AI(Claude)が一次情報をもとに作成していて誤りがありうる、大事な判断の前には必ず出典を開いて確認すること。
- レッスン・用語の末尾: 出典一覧(org + リンク)、「出典確認日 YYYY-MM-DD」(登録した出典のうち**最も古い確認日**を表示)、「本文はClaudeが出典をもとに作成した解説です」。
- クイズ解答時: 解説 + 用語リンク。ニュース: 原文リンクが主、要約は補助。確認日(`verifiedAt`)。
- 古い確認日の出典は、定期的に開き直して更新する対象(下記)。

## 4. 情報の更新運用
### 毎週のニュース(予定タスク。月曜 06:46 JST)
- 一次情報(JPCERT/CC、IPA)から新しい注意喚起を取り、`js/data/news.js` の先頭に追記するPRを出す。**新規が無ければ何もしない**(空PRを出さない)。
- 各記事: 原文を開いて確認 → id/date/org/severity/title/url/summary/points/terms/verifiedAt。関連する用語があれば `terms` に、無い用語は先に用語集へ追加(出典つき)。
- 別テーマで更新頻度が低いなら月次でよい。更新元の一次情報(公式発表ページ)を最初に決める。

### 毎日の改善(予定タスク。05:45 JST。現在は停止中)
- ROADMAP.md の「次にやること」の先頭から1〜2個。事実は一次情報を開いて確認 → sources.js に確認日つきで登録 → 書く。`node tools/check.js` と、幅390pxの全ルート巡回(エラー・横はみ出しなし)を通す。
- 毎日ブランチ(例 `daily/2026-11-01`)を切って PR。前日の PR が未マージならそのブランチから切って積み、PR説明に「#N を含む」と書く。マージはユーザー。
- 利用上限に達すると予定タスクが止まる(実際に発生)。翌日の回で再開すればよい。
- 現在は「バイト方式」(下記05)で SeEd 自身がコードを書く学習モードに移行したため、毎日改善は停止中。「再開して」と言われたら enabled を true に戻す。

### 出典の再確認
- 数か月ごとに出典のページを開き直し、内容が変わっていたら本文を直して `checked` を更新。リンク切れ・改訂(例: 「10大脅威 2026」「OWASP Top 10:2025」)は ROADMAP に残す。

## 5. 安全・倫理方針(攻撃・危険を扱うテーマの場合)
- 目的は防御。攻撃の「やり方」を教えない。模擬環境の中だけで動かす。実際のネットワークを攻撃しない。
- 「裏モード」(赤と黒の攻撃者視点)や実インシデント再現演習は、手順書や使える攻撃コードにせず、仕組みと検知・対策に留める。一次情報(報告書・公式発表)の出典つき、確認できた事実だけ。通常モードの見た目は変えず、切り替え式にする。
- 法的な線(不正アクセス禁止法など)は、専用の注意枠と練習場(RED LINE)で「どこからがアウトか」を体感させる。
- 別テーマ(医療・金融など)では同じ発想で **「この知識を使ってはいけない場面」「これは助言ではない」** の枠を必ず入れる。医療・法律・金融の具体的助言をアプリが断定しない。

## 6. 外部教材との連携方針(ユーザー決定 2026-11-04)
- 実践は既存の教材(例: PortSwigger Web Security Academy)に任せ、このアプリは**案内と記録に徹する**。外部教材の内容は転載せず、リンクと対応づけだけ。
- レッスンの `practice:[出典キー]`。`ST.LOCK` が "off" 以外のときは、レッスン完了後に表示(座学 → 手を動かす順)。
